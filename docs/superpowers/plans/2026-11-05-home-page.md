# Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Home tab, the default landing page, that shows today's cards (verdict first, then health and training signals with 7-day trends), lets the owner hide, show, reorder and reset them from a Customize sheet, and syncs that layout between devices.

**Architecture:** The four panels' hero and metric-card code is exported as small components that both the panels and a ten-card registry (`src/home/cards.tsx`) render; `HomePanel` lays the registry out on a phone-first CSS grid. The layout (`{ cards, updatedAt }`) lives in a small zustand store hydrated synchronously from localStorage and edited through pure functions in `src/home/layout.ts`; a native modal `<dialog>` with a dnd-kit sortable list edits it. In increment 3 a `/api/layout` function stores one row in Neon Postgres via `lib/settings.ts`, and the client pulls on entering Home and pushes 800ms after each change, newest `updatedAt` winning.

**Tech Stack:** React 19, TypeScript 6, zustand 5, react-router 8 (hash router), Chart.js 4 (untouched here), `@dnd-kit/core` 6.3 + `@dnd-kit/sortable` 10.0, `@neondatabase/serverless` 1.2, Vitest 5 (`node:assert/strict`), Playwright 1.64, Vercel functions.

**Spec:** `docs/superpowers/specs/2026-11-05-home-page-design.md`

## Global Constraints

- Build order: Home ships before Stylelint and visx. Chart.js stays; Home renders no charts. Stylelint may not exist yet, so new CSS must pass it later by construction: kebab-case class names, each selector written once per scope (no duplicate selectors), no `!important`, no inline `<style>`.
- Branch `home-page`. `commit "<msg>"` means `git -c user.name="Ryan Teo" -c user.email="ryanteo1996@gmail.com" commit -m "<msg>"`, with **no** `Co-Authored-By` or `Claude-Session` trailer. Never push unless asked.
- Each increment ends with `npm run check` exiting 0 and `npm run test:e2e` reporting no failures. Baseline today: 64 Vitest tests, 24 Playwright tests.
- Routes: `home` is `TABS[0]`, display name "Home". `/`, unknown hashes and unknown routes redirect to `/home` (both `src/App.tsx:32` and `src/main.tsx:22`). Legacy `#recovery`-style links keep working.
- Breakpoints for new CSS, phone-first with `min-width` only: `820px` (sidebar appears; sheet becomes a side panel) and `1061px` (four grid columns). Existing `max-width` rules are not edited.
- Grid: 2 columns base, 4 columns from 1061px. `span: 'full'` is `1 / -1` always; `span: 2` is `1 / -1` below 1061px and `span 2` from 1061px; `span: 1` is one column.
- Cards, default order, spans: `readiness` full, `hrv` 1, `resting-hr` 1, `sleep` 1, `body-battery` 1, `load` 2, `sessions` 2, `steps` 1, `intensity` 1, `stress` 1.
- Titles and groups (plan decision; the spec names only the two groups): Readiness, HRV, Resting HR, Sleep, Body Battery, Stress are `health`; Training load, Recent sessions, Steps, Intensity minutes are `training`. Group display names "Health" and "Training".
- Card id pattern (server): `/^[a-z][a-z0-9-]{0,31}$/`. At most 32 unique ids.
- Trend window on Home: 7 days (`series14(..., n = 7)`). Panels keep 14.
- `HomeLayout = { cards: string[]; updatedAt: number }`; the untouched default is `{ cards: DEFAULT_CARDS, updatedAt: 0 }`.
- localStorage key `home-layout` (value `JSON.stringify({ cards, updatedAt })`). Settings row key `home-layout`. Sign-out does not clear it in code.
- Sync: PUT 800ms after the last change; flush immediately with `keepalive: true` on leaving Home and on `pagehide`. GET on entering Home. 401 and network errors from `/api/layout` are ignored (local layout kept).
- API: `GET` → `200 { synced: true, layout: HomeLayout | null }` or `200 { synced: false }`; `PUT` → `200 { synced: true, layout }` (what is now stored) or `200 { synced: false }`; 401 unauthenticated (checked first); 405 other methods; 400 invalid/oversized/non-JSON body; 502 storage failure. Body limit is `readJson`'s default 4096. `updatedAt` must be a finite number `<= Date.now() + 86_400_000`.
- Storage: `DATABASE_URL` env var; table `settings (key text primary key, value jsonb not null)` created with `create table if not exists`, once per process.
- Packages, exactly: `@dnd-kit/core@^6.3.1`, `@dnd-kit/sortable@^10.0.0`, `@neondatabase/serverless@^1.2.0`. Not `@dnd-kit/react`, not `@dnd-kit/utilities`.
- Customize sheet: `<dialog>` via `showModal()`, accessible name "Customize Home". Phone: full width, `max-height: 85dvh`, `border-radius: 14px 14px 0 0`, bottom safe-area padding. From 820px: 360px wide right-hand panel, full height, transparent `::backdrop`. Rows and every control in it at least 44px tall. Handle named "Move {title}" with `touch-action: none`; switch is `<input type="checkbox" role="switch" aria-label="Show {title}" id="show-{id}">`. Footer buttons "Reset to default" and "Done".
- Announcement on lift, verbatim: `Picked up {title}, position {i} of {n}` (1-based, `n` = shown count).
- Reduced motion: no code needed; `src/style.css:236` already forces `transition: none !important` and beats dnd-kit's inline transitions.

## Review Focus

Failure modes the spec implies that no unit test reaches; each is pinned to a step.

1. **Extracted Home cards lose "which day is this from".** The readiness chip ("Based on Nov 3, not today…") and the "From Nov 3" sub-line must render on Home exactly as on Recovery (Task 5 Step 4 e2e with the latest HRV removed).
2. **Recovery or Training silently changes after extraction.** The load line, "How is this scored?", the 14-day sparkline label, and the sessions list inside Training's hero must stay (Task 2 Step 1 and Task 3 Step 1 e2e, written before the refactor).
3. **Escape during a keyboard drag closes the whole sheet** instead of cancelling the drag, and the dnd-kit live region is portalled outside the modal (inert, so silent) (Task 6 Step 5 e2e).
4. **A remote layout lands while the sheet is open** and yanks rows from under the owner's hand (Task 12 Step 6 e2e with a delayed GET).
5. **First paint shows the default layout, then jumps** to the saved one because hydration ran in an effect (Task 8 Step 5 e2e with a MutationObserver).

Also pinned, cheaper: a stored layout with ids no longer in the registry (Task 7 `sanitize` test, Task 8 Step 5 seeded `gone` id); signed-out 401 on layout calls (Task 12 Step 6); the range `<select>` and its `aria-describedby` target both absent on Home (Task 4 Step 6); `#recovery` and unknown hashes (Task 4 Step 6).
